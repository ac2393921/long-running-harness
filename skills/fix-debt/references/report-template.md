## ファイル名

`debt-analysis-YYYYMMDD-HHMMSS.md`

例: `debt-analysis-20250130-143022.md`

## レポート構造

### 1. ヘッダー

```markdown
# 技術的負債分析レポート

**分析日時**: YYYY-MM-DD HH:MM:SS
**分析者**: Claude Code
**プロジェクト**: [プロジェクト名]

---
```

### 2. サマリー

```markdown
## サマリー

**分析対象**: [ファイルパスまたはディレクトリ]
**適用基準**: [使用した基準ファイルのリスト]
**検出問題数**: [合計数]

- 🔴 高深刻度: [数]
- 🟡 中深刻度: [数]
- 🟢 低深刻度: [数]

### 基準別の検出内訳

- **条件分岐**: [検出数] 件
- **カプセル化**: [検出数] 件
- **関心の分離**: [検出数] 件

---
```

### 3. 詳細レポート

各問題について以下の形式で記載:

```markdown
## 詳細レポート

### 問題 #[番号]: [問題の簡潔な説明]

**基準**: [適用した基準ファイル名]
**深刻度**: [🔴 高 / 🟡 中 / 🟢 低]

#### 検出情報

- **ファイル**: [`[ファイルパス]:[行番号]`]([ファイルパス]#L[行番号])
- **クラス/関数**: `[名前]`
- **問題パターン**: [パターン名]

#### 具体的な問題点

[問題の詳細説明]

**問題のあるコード:**

\`\`\`[言語]
[コードの抜粋]
\`\`\`

**違反している原則:**

- [原則1]
- [原則2]

**潜在的なリスク:**

- [リスク1]
- [リスク2]

#### 改善提案

**適用すべき設計パターン/手法**: [パターン名/手法名]

**改善後のコード例:**

\`\`\`[言語]
[改善されたコード]
\`\`\`

**期待される効果:**

- [効果1]
- [効果2]

#### 影響範囲

- **変更が必要なファイル数**: [数]
- **関連する他のクラス/モジュール**: [リスト]
- **テストの必要性**: [高/中/低]
- **後方互換性**: [考慮事項]

---
```

## 深刻度の判定基準

### 🔴 高深刻度

- セキュリティリスクのある問題
- 重大なバグを引き起こす可能性が高い問題
- パフォーマンスに大きな影響を与える問題
- メンテナンス性を著しく損なう問題

### 🟡 中深刻度

- 将来的にバグの原因となる可能性がある問題
- コードの可読性を損なう問題
- テスタビリティに影響を与える問題
- 小規模なパフォーマンス問題

### 🟢 低深刻度

- コーディングスタイルの問題
- 軽微な可読性の問題
- 将来的なリファクタリングの候補
